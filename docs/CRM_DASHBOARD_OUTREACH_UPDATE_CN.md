# JerseyAtlas Creator CRM v3.0 — 仪表盘账号独立统计更新

本次更新基于用户上传的完整 CRM 项目 ZIP。仅更新前端页面和本说明文件；不重置 Supabase 数据库，不删除历史达人、合作、视频、奖励或跟进记录。

## 仪表盘

- 蓝色 KPI「达人总数」保留原有累计总数。
- 新增「今日 / 本周建联数据」表，按达人资料中的「建联账号」（`messaging_account`）分别统计。
- 本周口径：周一至今天（含今天）。
- 新增「今日私信达人账号」列表，显示达人名称、@用户名、平台、建联账号、建联状态和首次私信日期。
- 保留原有「最近更新的达人」区域。

## 新增达人默认规则

- 手动新增达人保存时，系统强制将建联状态设为「已私信」。
- 首次私信日期默认今天；用户可在保存前修改日期。
- 新增达人必须填写「建联账号」，以便按账号统计今日 / 本周建联数据。
- 历史记录不会被批量改写；历史记录的建联账号为空时保留为空，不猜测归属。
- 编辑旧记录时，不强制补填建联账号，也不会因为原首次私信日期为空而自动写入今天，避免污染历史统计。

## 跨账号去重

- 所有建联账号共用同一达人库。
- 同平台 @用户名或主页链接重复时，前端提示已由哪个建联账号添加。
- 前端检查覆盖当前登录用户通过 Supabase RLS 可读取的达人记录；多个用户并发提交时，最终仍需数据库唯一索引兜底。
- 本次 ZIP 未包含 `creators` 表的完整建表 / 索引 DDL，因此无法仅凭 ZIP 核实线上是否存在 `creators_platform_handle_unique` 和 `creators_platform_url_unique`。上线前可在 Supabase SQL Editor 执行以下只读查询核验：

```sql
select indexname, indexdef
from pg_indexes
where schemaname = 'public'
  and tablename = 'creators'
  and indexname in ('creators_platform_handle_unique', 'creators_platform_url_unique');
```

- 如果查询没有返回这两个索引，不要直接创建索引；先检查现有重复数据，再单独评估数据库变更。

## 合作状态分组

- 建联与跟进页面将「已合作达人」和「暂停合作达人」分成独立区域。
- 待联系、意向、合作及暂停合作状态仍保留在原达人记录中。

## 竞品字段

- 从达人录入界面和达人列表中隐藏竞品外链字段。
- 数据库原字段以及导入 / 导出兼容字段保留，不删除历史值。

## 数据库兼容性

- 本次沿用已有的 `contacted_at` 和 `messaging_account` 字段，不新增表，不执行破坏性 SQL。
- 上传的 2026-11-18 业务数据快照包含 16 条达人、7 条合作、4 条视频、10 条奖励档位和 1 条跟进日志；达人记录已包含 `messaging_account` 字段，但当前历史值为空。
- 本次没有对业务 JSON 备份执行导入，也没有对线上 Supabase 执行写操作。
